# Bahrain–Iraq Recon Studio: Dataiku installation

1. Create a **Standard Webapp** in the Dataiku project.
2. Copy `webapp.html`, `webapp.css`, `webapp.js`, and `backend.py` into the corresponding WebApp editors.
3. Copy the entire `bahrain_iraq_algorithm` folder into the project Python library. The library name must remain `bahrain_iraq_algorithm`.
4. Add `pandas`, `openpyxl`, and `numpy` to the Dataiku code environment used by the WebApp. Only if you upload old `.xls` / `.xlsb` workbooks, also add `xlrd` (for `.xls`) and `pyxlsb` (for `.xlsb`); `.xlsx` / `.xlsm` need nothing extra.
5. Restart the backend and open the WebApp.

The library folder holds `engine.py`, `depth_search.py`, `translation.py`, `outstanding_report.py`, `default_report.py`, `pdf_simple.py` and `default_mapping.json`. Always copy the **whole folder** together with `backend.py` and the three webapp files: `backend.py` and the library are updated as a pair. If the library is older than the backend, the rest of the app keeps working and the affected page (Depth Search, Default Mapping, Off-Balance, or the Arabic prompt) tells you which file to update.

## Workflow
- Upload the Trial Balance; the engine detects its header row and builds the summarized pivot plus a group/sub‑group hierarchy tree (split from the BS Mapping column).
- Upload up to eight submission workbooks (e.g. a separate Assets file, a separate Liabilities file, and a few more). Every sheet of every uploaded file is inspected — header row, currency columns (USD/IQD/BHD/…, including a `'000`/`million` scale) and a Total column are detected automatically, but nothing is read until you tick the sheets you want (and optionally correct the header row) in the sheet picker.
- Extraction reads each selected sheet structurally: bold/indented rows become section and sub‑section headers, "Total …" rows are flagged, and every numeric cell is tagged with its currency, scale and exact cell reference.
- The engine proposes candidate reconciliation rules automatically: Assets↔Assets, sub‑group↔sub‑group, and currency‑for‑currency / Total‑for‑Total, with an inferred sign convention. When the blanket "sum every line in this section" total doesn't reconcile and there's no sheet-provided Total row to trust, it also runs a bounded subset search over that same section's lines and — if some specific subset does reconcile — adds it as a second, clearly labelled "Auto‑clubbed subset" suggestion alongside the blanket one, explaining which line(s) it excluded. Nothing is applied until you approve each suggestion in Mapping Studio, and the two never auto-approve simultaneously for the same group/currency.
- **Reporting-scale mismatches (thousands/millions) are checked two ways.** At extraction, a column header's own text (`'000`, `thousands`, `million`) sets the scale automatically. Separately — and this matters when the header gives *no* textual clue at all while the values are quietly divided by 1,000 or 1,000,000 — every suggestion, manual match and re-imported mapping is also checked *numerically*: if the values don't reconcile at face value but do after applying a common scale factor (and/or a sign flip), that's surfaced as a clearly labelled "Scale-adjusted" suggestion (or applied automatically in the manual builder, with the applied factor always shown, never hidden).
- You can download the extracted submission lines as a standalone, simplified workbook at any point after extraction (Submissions step) — independent of the full audit export.
- For anything the auto-matcher missed, build a **manual match**: multi-select any combination of Trial Balance items on the left and submission lines on the right and give it a short description. The running totals on both sides update live as you select, including a live warning if a scale/sign adjustment would be needed to reconcile them.
  - The TB side has two levels, toggled above the list: **Accounts** (pick individual GL accounts) or **BS Mapping groups (pivot level)** — one row per BS Mapping group/sub-group and currency, matching the TB Pivot page exactly. Picking a group row clubs every account underneath it in one click (search e.g. a group code or name, tick it, done) instead of hand-picking each account. Account-level and group-level picks can be freely mixed in the same match — overlapping accounts are automatically de-duplicated, so selecting a whole group and one of its own accounts never double-counts.
  - **Account description / Account no. switch** (top of Mapping Studio): the same account often appears several times in a TB — one description under several account numbers, or one number with several postings or names. The switch chooses whether the Accounts picker *and* the Trial Balance side of every match card (including default-mapping matches) are folded into one row per **description** (default; account numbers listed beside it) or per **account number**, with amounts summed. This is display/picking only: the underlying lines, and what the reconciliation and exports use, are unchanged. Switching keeps a pick only if every line behind it is still covered, and tells you if any were dropped.
  - **FRX\* = Forex sub-total.** Local currency is IQD (`LOCAL_CCY` in `engine.py`). Wherever a group or account has any non-IQD balance, an `FRX*` row is offered next to its per-currency rows: the sub-total of *every* non-local currency (also a `FRX*` column in the TB Pivot, the group chips and the export). Pick `FRX*` instead of USD/EUR/… and the saved mapping stores `currency: "FRX"` by name, never a list of currencies. When that mapping is re-applied to another period's file, the engine re-totals whatever foreign lines the account has at that time, so a newly appearing currency is included automatically; each match card/audit evidence still shows the per-currency breakdown. An account that has no foreign balance this period resolves to an FRX of 0 (not a "not found" warning). Search `frx*` in the picker to list just the Forex rows. Note the mapping still names accounts/descriptions: a brand-new *account* with foreign balances is not picked up, only new currencies on mapped accounts.
  - "Select all matching" / "Clear" above each list bulk-select or bulk-deselect everything the current search matches (not just what's currently rendered), on both the TB and submission sides.
  - **Search by amount, not just by text**: club up whatever Trial Balance items you want (individual accounts and/or whole BS Mapping groups), then click "Search submissions for the TB selected total" — it searches *every* extracted line, across every sheet and every submission file, for a value that equals that total, either at face value or after a common scale factor (thousands/millions) and/or a sign flip. Each hit shows exactly where it is (file, sheet, cell, description) and which transform matched; "+ Add" drops it straight into the submission side of the match with that exact transform already applied, so a value you know but can't place gets you straight to the cell instead of scrolling through hundreds of lines by hand.
- **Equal-and-opposite values reconcile.** Liabilities, capital and similar lines are often negative in the Trial Balance and positive in a submission (e.g. -124,591,456 vs 124,591,456). The manual builder's live preview, the match itself, auto-suggestions and re-applied saved mappings all treat a pure sign flip (with or without a thousands/millions scale) as a match: the submission side is stored with `sign: -1` so the reconciliation shows a difference of 0, and the match card carries a "Sign flipped" tag. Nothing is flipped unless the flipped values actually reconcile within tolerance.
- **Same description on several lines/sheets? The Trial Balance amount decides.** A saved or default mapping only stores a submission *description*, and that label often recurs (other sections, the Assets / Maturity / Foreign-Currency sheets, other files). When more than one line matches (name similarity within 0.05 of the best), the engine picks the hit — or, if the mapping has several submission items, the combination of hits — whose amount equals the Trial Balance amount: exactly at face value first, then allowing a thousands/millions scale and/or opposite sign. Every disambiguation is listed in that match's warnings ("N submission lines match …; picked Sheet!Cell because its amount agrees"). If nothing agrees, it takes the best name match and says so ("none agrees … please review") instead of silently guessing. **Auto-suggestions do the same:** when a section label appears on more than one sheet/file, each (file, sheet) is judged on its own — never added together — and the one whose amount agrees with the TB (exactly, or via a scale/sign fit) is kept; the suggestion card says which sheets competed and which was picked.
- **Save/load a mapping**: download everything you've built as a portable JSON mapping file, then re-upload it after a future period's Trial Balance and submissions are processed — each match is re-resolved against the *new* data (primarily by account **description** + BS Mapping, never by account number — chart-of-accounts numbers get renumbered/reused far more often than a line's own description changes) and added back for review, with any low-confidence or unresolved items flagged rather than silently applied.
- **Mapping Coverage** (its own page) is the detailed accounting of every rule in the bundled default mapping: how many were *fulfilled* (data found on both the TB and submission sides), how many were *unresolved* (with the exact reason — which account or line wasn't found), and — once you run the reconciliation — how many actually *reconciled* versus need review. Filterable and searchable, and the same detail is written to the exported workbook as its own "08 Mapping Coverage" sheet, so the coverage picture survives outside the app too.
- **The bundled default mapping is now your supplied one (33 matches: Assets, Liabilities, forex `FRX`, per-currency USD/EUR/GBP, and `TOTAL` rules across the Assets, Liabilities, Assets by Foreign Currency, Assets by Maturity and Schedule 4-A sheets).** To change it again, replace `bahrain_iraq_algorithm/default_mapping.json` (a mapping file downloaded from Mapping Studio works as-is). Because it lists an account once per raw TB line, resolution counts each account's lines once, and **an item that names a currency takes only that currency's lines** — if this period's TB has no such line (e.g. no AED balance) the item is reported missing in Mapping Coverage instead of absorbing the other currencies. `TOTAL` and `FRX` are the only multi-currency items. It contains no `OB-` rules: Off-balance is covered by Depth Search. **A bundled default mapping is resolved automatically, every extraction, with zero upload step.** `bahrain_iraq_algorithm/default_mapping.json` (swap it for your own chart of accounts' mapping) is a portable, name-only mapping — never a cell address — resolved fresh against whatever TB and submissions are loaded each session. Matches it finds land straight in Manual matches, tagged `DEFAULT`, fully reviewable and removable before you run the reconciliation; anything it can't find in the current data (a different chart of accounts, a sheet that wasn't selected for extraction) is silently left out rather than cluttering the review list with pure misses.
- **Default Mapping** (its own page; it opens by itself after you extract the submissions, and needs no upload step). The bundled `default_mapping.json` (version 2, 31 templates) is applied to every extracted file and each rule is reported with its **Trial Balance amount, submission amount, variance (TB − submission), variance % and status**: *Match*, *Match (within tolerance)* (within the absolute / % tolerance you can change on the page, or within the rounding of a sheet stated in thousands — the note says which), *Variance – review*, or *Not found* (with the reason: e.g. the target sheet was not selected for extraction). Rules that are shown:
  - **Group rules** (`"rule_type":"GROUP_RULE"`, TB item `{"level":"group","bs_mapping","currency","sign_filter","include_desc","exclude_desc",...}`) take a whole BS-mapping group at *account* level, so **new accounts in the group are picked up automatically**. `currency` is `IQD`, a code such as `USD`, `FRX` (every non-IQD currency) or `TOTAL`; `sign_filter` is `positive`/`negative`; `include_desc`/`exclude_desc` are case-insensitive regexes on the account description. The shipped rules use this for A-IGA, A-FA (all / positive without depreciation and capitalised software / negative / capitalised software only), A-CBI + A-CRR, A-OA and L-CASA / L-IGL.
  - **One cell per currency on the submission side.** A rule finds the row by its description. On **Assets** a TB group's IQD subtotal is found in **one** of the two IQD columns (3 = G Residents or 4 = H Non-Residents) — **never as their sum** — and its foreign-currency subtotal in **one** of the two foreign columns (5 = I or 6 = J); the Total (column 2 = F) is a single cell. The engine takes the cell that agrees with the TB amount (exactly, or allowing a thousands/millions scale); if none agrees it shows the closest one with a note ("the Trial Balance amount is in none of the IQD columns of the row"), so a real variance is visible instead of being hidden by adding the columns. A row with nothing in that currency counts as zero. A rule item can still say `"aggregate":"sum"` to add the cells up, and rules that carry a `column_context` keep single-cell behaviour.
  - **`FC_COLUMNS` rules** (A-CBI + A-CRR, A-IGA, A-OA on *Assets by Foreign Currency*) expand when applied: one rule for each currency column the sheet actually has (USD, EUR, GBP, …) plus **Other Foreign Currencies** — all remaining foreign currencies on the TB, matched with the sheet's "Other" column. Currencies with nothing on either side are dropped.
  - **Rules from `Iraq Changes.docx` — for Assets and for Liabilities (`ASSET_GROUP` / `LIABILITY_GROUP` templates).** One template per BS-mapping group (or groups) and sheet row — e.g. `{"rule_type":"ASSET_GROUP","label":"A-FA Fixed Assets (A + B)","tb_groups":["A-FA"],"row":"Fixed Assets (A + B)"}` or `{"rule_type":"LIABILITY_GROUP","label":"L-OL Liabilities Other","tb_groups":["L-OL"],"row":"Liabilities Other ( Considered Statement Accordingly )"}` — expands when applied into the standard checks: **main sheet IQD (column 3 or 4) = TB group IQD**; **foreign (column 5 or 6) = TB group, every non-IQD currency**; **total (column 2) = TB group, all currencies**; **"<Assets|Liabilities> by Foreign Currency" = currency to currency, and every other currency against "Other Foreign Currencies"**; and the **"… by Maturity"** total. Liabilities templates use `sign -1` (TB balances are negative, the sheet shows positive amounts). The sheet names are read from the extracted sheets (any sheet starting with Assets/Liabilities and containing "foreign"/"curren" or "maturity"/"period" — so `Liabilities According to Period` is the maturity sheet and `Liabilities According to Curren` the foreign-currency sheet; if a sheet's headers are not recognised as IQD / foreign currency, every cell of the row is tried and the one that equals the TB amount is used); a foreign-currency or maturity sheet that was not extracted is skipped and the page says so. Each file's card also lists the sheets that were read from it, and warns when no rule found a cell in it. Optional fields: `include` (subset of `IQD`,`FRX`,`TOTAL`,`FC`,`MATURITY`), `row_foreign`, `row_maturity`, `sheets`, `sign`. A check that an explicit rule already makes is dropped, so nothing is counted twice. Shipped for Assets: A-CBI + A-CRR, A-TB, A-FA, A-OA and a **Total Assets check** (`"A-*"` = every group starting with `A-`); for Liabilities: L-CASA, L-IGL-C + L-IGL-F, L-OL, L-PR, L-PL, L-CAPITAL and a **Total Liabilities check** (`"L-*"`, assumes a row called "Total Liabilities" — change `row` if yours differs). To cover another group, add one more template. **Not templated, on purpose:** rules that use fixed or individual accounts or exclusions (#1, #3, #5–7, #12, #14), **L-PYR** (see above) and **A-IGA** (IQD to *Head Office and Branches*, forex to *Debit Balances with Banks*).
  - **Off-balance checks (from the Outstanding Report, same basic rules).** When an Outstanding Report is loaded and the extraction contains the off-balance sheets — found by name: `Off-Balance Sheet Accounts` (main), `… by F` / `by Foreign Currency` and `… by M` / `by Maturity` / `by Period` (Excel cuts names at 31 characters) — rules are generated for the **Total**, every **CATEGORY** and every **LC/GTEE DESC** row (the row is found on the sheet by its description): **main sheet** IQD (column 3 or 4), foreign currencies (column 5 or 6) and total (column 2) against **Pivot 1** (rows LC/GTEE DESC × columns BILL_CCY); **by-currency sheet** currency by currency and the rest against "Other" (Pivot 1); **by-maturity sheet** the total plus **one check per maturity bucket column** against **Pivot 2** (rows CATEGORY › LC/GTEE DESC › BILL_CCY × columns Bucket). Buckets are paired with the sheet's maturity columns by their upper bound (`1M` / `0-30 Days` ↔ "Less than one Month", `3M` / `31-90 Days` ↔ "Between One and Three Months", …, "Above 365 Days" ↔ "More than five years"), falling back to left-to-right order when the counts agree; each rule's name states the column used, and if the two cannot be paired only the maturity total is checked (the page says so). A maturity-bucket header is now read as currency `BUCKET` so its cells are extracted. Off-balance rules appear on the Default Mapping page, the PDF and the OB file's workbook (with the **OB Pivot 1** (currency) and **OB Pivot 2** (bucket) sheets coloured like the TB Pivot), but not in Mapping Studio. The row labels of the sheet must resemble the LC/GTEE DESC / CATEGORY values (or "Total Off-Balance Sheet Accounts" for the total row); rows that do not show as *Not found*. Upload the Outstanding Report before the submissions, or press **Re-run** after uploading it.
  - **"Trial Balance groups and the rules that read them"** (a panel on the page, a section of the PDF and a sheet in each workbook) lists every BS-mapping group with its IQD / foreign / total amounts and the rules that use it; a group with a balance that no rule reads is marked **NO RULE**.
  - **Liabilities rules are BS-group aggregates, not fixed accounts:** L-CASA, L-IGL-C + L-IGL-F, L-OL, L-PR, L-PL, L-CAPITAL in IQD (`GROUP_RULE`, one group item each) and the five forex rules (L-CASA, L-OL, L-PR, L-PL, L-CAPITAL, `FRX` = every non-IQD currency, read from the foreign-currency columns); new accounts in a group are picked up automatically. **Reserve Mandatory and Profits And Losses Carried Forward stay single-account rules** (208701 and 208301): both accounts sit in the `L-PYR` group, so grouping either would mix the two rows.
  - **Output by file**: each submission file gets `<file>_DefaultMapping.xlsx` (and a zip of all) — your original sheets with matched cells highlighted and a hover comment naming the rule and its variance, **TB Pivot** and **TB Accounts** coloured the same way, **Default Mapping Report** (rule, how it works, TB amount, submission sheet/cells with a clickable link, submission amount, variance, variance %, status, notes), **Default Mapping TB Detail** (every TB account behind each rule) and **Default Mapping Summary**.
  - **PDF**: "Download PDF (all results)" produces one document with the summary, results by rule, a rule-by-rule detail (TB side and submission side), the Mapping Studio auto-suggestions with their approval decision, and the manual / imported matches. It is written by `pdf_simple.py` with no extra package (Helvetica), so **only Latin text can be drawn — Arabic appears as `?`**; translate the submissions first if the PDF must be readable.
  - Every default match is still added to Mapping Studio (source `DEFAULT`) and each Mapping Studio match card now shows its variance and variance %.
- **Depth Search** (its own page, right after Submissions; needs only the TB and the *uploaded* workbooks, no extraction). It looks for the Trial Balance pivot values at **BS-mapping level** (every currency column, the `FRX*` sub-total and the Grand Total) and at **group roll-up level** (e.g. all of `Assets`) in **every non-zero numeric cell of every sheet** of each submission file — including the schedule/matrix sheets the structural extractor never reads. Optionally also account-level values. Details:
  - **File routing.** Each file is typed (guessed from the name, in English or Arabic: `033`/asset/الأصول → Assets, `034`/liabilit/المطلوبات → Liabilities, `064`/off-balance/خارج الميزانية → Off-balance; changeable per file). `A-…` / `Assets…` values are searched in the Assets file, `L-…` / `Liabilities…` in the Liabilities file, and **`OB-…` (off-balance) values only in the Off-balance file — never in Assets or Liabilities, and Assets/Liabilities values are never searched in the Off-balance file**. "Other — search everything" files get everything.
  - **How a cell matches.** Exactly (within the absolute tolerance), or after a ×1,000 / ×1,000,000 scale (sheets stated "Amounts in Thousand Iraqi Dinars" — a match that uses the sheet's own stated scale is marked so; the rounding allowance follows the cell's decimals), and/or with the opposite sign (liabilities). Tiny TB values are not searched (default minimum 1,000; 100,000 for a scaled match) to keep coincidences out; the whole-TB grand total is never searched (it nets assets against liabilities). Mappings or groups holding the same figure are searched once and all their pivot cells are highlighted.
  - **Currency sanity.** Each column's currency is read from its own header (nearest header text first, forward-filled across grouped columns): `US Dollar` → USD, `Accounts in Iraqi Dinars` → IQD, `Foreign Currency Accounts Converted to Iraqi Dinars` → FRX, `Total` → TOTAL; a sheet-wide unit note never overrides it. USD is only matched with USD, IQD with IQD; a clash (e.g. an IQD amount under a "Euro" column) is **listed but not highlighted** and marked CONFLICT; an unrecognised column (e.g. maturity buckets) is UNKNOWN and still highlighted.
  - **Off-balance file = two sources.** The file typed Off-balance is searched with every `OB-…` BS-mapping value from the TB pivot **and** every value of the two Outstanding Report pivots; its result card states how many of each were searched.
  - **Output, one workbook per file** (`<file>_DepthSearch.xlsx`, plus a zip of all): your original sheets untouched apart from the highlight and a hover comment on each matched cell, then **TB Pivot** (BS-mapping rows, group roll-ups, currency columns, FRX*, Grand Total), **TB Accounts**, **Matching Report** (what matched what: TB item, currency, amount, file/sheet/cell with a clickable link, cell value, transform, row label, column header, column currency, currency check, how many cells hold that amount, pivot cell), **Unmatched TB Values** and **Depth Search Summary** (counts, settings, warnings). A TB value and every cell where it was found share one fill colour, in the TB Pivot and in the submission sheets, so each match can be followed by colour.
  - **Limits to know.** Formula cells are read from Excel's saved results — a file that was never recalculated in Excel shows a warning and those cells are skipped. The annotated copy is rewritten with openpyxl: cell values, formulas, formats and comments are kept, but embedded charts/images/pivot tables in the original are not carried over (the original file is never modified). Numbers stored as text are searched too. Needs `bahrain_iraq_algorithm/depth_search.py` in the project library (copy the whole folder); without it the rest of the app keeps working and the depth-search page explains what to update.
- **Off-Balance / Outstanding Report** (its own page, step 3: upload it after the Trial Balance and before the submissions — it is optional, and **used only to reconcile the Off-balance (064) submission**). Upload the Outstanding Report workbook (`.xlsx`, `.xlsm`, `.xls`, `.xlsb`). The raw-data sheet and its header row are **found from the data** (first 20 rows scanned; the five mandatory fields CATEGORY, BILL_CCY, LC/GTEE DESC, Equ-IQD and Bucket must resolve; spelling/spacing variants such as `Equ IQD`, `LC / GTEE DESC`, `BILL CCY` are equivalent; existing PivotTable, summary and exchange-rate sheets are ignored). Equ-IQD is cleaned (commas, symbols, `(1,234)` negatives, text numbers) and **never silently turned into 0** — blank/invalid rows are excluded and counted in the Validation table; blank groupings show as `(blank)`; currency codes are upper-cased; repeated header rows are dropped; duplicates are reported, not removed. Two pivots are built exactly as specified: **Pivot 1** — rows LC/GTEE DESC, columns BILL_CCY, values Sum of Equ-IQD — **CATEGORY is not used and there is no filter**; **Pivot 2** — rows CATEGORY › LC/GTEE DESC › BILL_CCY, columns Bucket (ordered by a lower bound read from the label, never alphabetically), values Sum of Equ-IQD, no filter. Grand totals are reconciled to the cleaned source. "Download pivot workbook" gives `Source_Cleaned`, `Pivot_LCGTEE_Currency` (Pivot 1), `Pivot_Category_Bucket` (Pivot 2) and `Validation`, formatted as specified. In **Depth Search** both pivots become extra search targets for the file typed **Off-balance (064)** and no other file — not even a file typed "Other — search everything". If none of the uploaded files is typed Off-balance (for example the file name has no `064`), the Depth Search page warns before and after the run and the pivots are not searched; set the type under "What is each file?" and run again. They are shown in the Off-balance file's output as `OB Pivot 1` / `OB Pivot 2` with the same colour highlighting. **The Bucket (tenure) pivot (Pivot 2) is searched on Maturity sheets only** (sheet-name keywords `maturity, tenor, tenure, استحقاق…`, editable on the Depth Search page); Pivot 1 is searched on every sheet. If the Off-balance file has no maturity-named sheet, the Bucket pivot is skipped with a warning rather than matched against the wrong sheets. **The two pivots are plain Excel-style pivots — no cleaning rules.** They sum the numeric cells of the `Equ-IQD` column only (never Bill Amount, Rate, Deal Bal or the exchange-rate sheet), group by the labels exactly as written (an empty label shows as `(blank)`; nothing is trimmed, upper-cased or merged), and ignore empty and text cells the way an Excel PivotTable does — so *Pivot total* always equals *Excel SUM of the raw column* (the page shows both). Nothing is corrected or excluded silently: rows that are not in a total (empty Equ-IQD, text such as `N/A` or `1,310,000`) and rows that look like a total line typed under the data (which **is** counted, as Excel would) are only *listed* — in the page's notes, the Validation sheet and the **Row_Exceptions** sheet (with the Excel row number) — so you can see why a total differs from what you expected. Only the raw-data sheet and header row are detected automatically, and completely blank rows and header rows pasted again inside the data are skipped.
  - **Pivot builder (Off-Balance page → "Pivot builder").** The two pivots are created automatically and are used as they are (status chip: *Automatic pivots*). If a total or value looks wrong, pick the **sheet**, the **header row** and the **column for each role** — Pivot 1: item (LC/GTEE DESC), currency (BILL_CCY), amount; Pivot 2: category (optional), item, currency, bucket, amount — and press **Build pivots**. That makes a **draft** that is used nowhere. For each pivot it shows the amount column, rows read / summed / ignored (empty or text), blank labels, the **Excel SUM of the raw amount column**, the pivot total and their difference (plus any formula cells that were never calculated, and the list of rows that are not summed normally); you can also type **your own Excel total** to compare. **Approve and use these pivots** makes the draft the active pivots (status *Approved custom pivots*): the off-balance checks on the Default Mapping page and the Depth Search then use them (the Default Mapping results are re-run automatically). **Use the automatic pivots** goes back. **Save these pivots as my default (library)** writes `pivot_definition.json` into the `bahrain_iraq_algorithm` folder; from then on every new Outstanding Report is built with that definition automatically (status *Saved pivot definition*), and if it no longer fits the report (a column is missing) the automatic pivots are used and the page says why. If the library folder is not writable from the webapp, use **Download the definition** and copy the file into the library folder yourself (**Load a saved definition file** reads it back into the builder). The definition holds only names (sheet, header row, column labels) — never cell addresses.
  - **Off-balance: forex, "For Other Purposes" and the maturity columns.** *Pivot 1 now has a **Forex (non-IQD)** column* (every currency except IQD, next to the Grand Total — like the Trial Balance pivot's FRX*; it is not added into the Grand Total twice). The main sheet `Off-Balance Sheet Accounts` is checked like Assets and Liabilities: **IQD in column 3 or 4, foreign-currency total in column 5 or 6, total in column 2**, each from Pivot 1. A sheet row that gathers several LC/GTEE items is declared in `default_mapping.json` → `"ob_row_groups"`: the shipped one is **For Other Purposes = ADVANCE PAYMENT BOND + LTR OF INTENT + OTHERS - CGT (TXN) + GOODS/SERVICE G'TEE** (names compared ignoring case, spaces and punctuation); the sum of those items' IQD, foreign and total is checked on that row in the main sheet (columns 3/4, 5/6, 2), on the same row of the by-currency sheet (currency by currency) and of the by-maturity sheet (each bucket); those items are then not checked separately. Add more entries for other gathered rows. **Maturity:** the Pivot 2 buckets `1M, 3M, 6M, 1Y, 1-5Y, 5Y` are paired with the sheet's `Less Than One Month`, `Between One and Three Months`, `Between Three and Six Months`, `Between Six Months and One Year`, `Between One and Five Years`, `More than Five Years` (a bare `5Y` is read as "more than five years", `1-5Y` as the range). An Outstanding Report item or category is checked on its own only when the sheet has a row of the same name; the others are listed in a note (they remain inside the totals) so a row that merely sounds similar can never give a false variance.
  - **Off-balance depth search (the general search for the off-balance accounts).** Besides the row-by-row checks, **every value of Pivot 1 and of Pivot 2** (each item, currency, Forex, bucket and total, and every category / item / currency sub-total of Pivot 2) is searched in **every non-zero cell of the off-balance workbook** — with the same engine as the Depth Search page: thousands / millions scale, equal-and-opposite sign, a currency-column check (a EUR value is only accepted in a EUR column, foreign in 5 or 6, IQD in 3 or 4; a maturity-bucket column holds every currency), and the bucket pivot on the maturity sheet only. One line per distinct value, tagged **(depth search)**: *Match* with the sheet, cell, row and column it was found in, *Variance - review* if it is only found in a column of another currency, or *Not found*. Depth-search values are counted apart from the rules (a KPI card "Depth search: pivot values found x / y", a chip on the file's card, a line in the PDF summary); the cells found are coloured in the file's workbook and on its **OB Pivot 1 / OB Pivot 2** sheets (the exact pivot cell that was searched). They appear in the PDF's results table but not in its rule-by-rule detail. A pivot value that is legitimately not on the sheet (for example an item the sheet only shows inside a gathered row) is *Not found* here, so read that list as "where does each pivot number show up". Switch it off with the checkbox on the Default Mapping page. The off-balance workbook must be in the session (the original file is read).
  - **Column value search (Assets, Liabilities and Off-balance alike).** When a rule's own row does not give the amount (the row label is not recognised, or the row holds another number), the run looks **thoroughly** at the column that belongs to the rule's currency on the rule's sheet — EUR → the EUR column of the by-currency sheet (`Assets by Foreign Currency`, `Liabilities According to Curren`, `Off-Balance Sheet Accounts by F`), USD → USD, "Other" → the other-currencies column, IQD → columns 3 and 4, foreign → 5 and 6, Total → the total column, a maturity bucket → that bucket's column: (1) a **single cell** equal to the amount (equal-and-opposite sign accepted and noted, thousands rounding allowed); (2) else the **sum of the column** — every cell, every cell except the rows marked total, or every cell except the largest one (a total row that carries no "Total" label) — so a total that is not written anywhere is still found; (3) else nothing is claimed but the **closest value** is reported in the note (cell, row, difference). Totals of **Assets and Liabilities** are searched the same way as the off-balance ones: a total whose row label cannot be read is found by its value in the right column (IQD → column 3 or 4, foreign → 5 or 6, Total → the total column, each currency → its column on the by-currency sheet, the maturity total → the total column of the by-maturity sheet); on a hierarchical statement where the total line is missing, the **numbered top-level lines** (those with a serial number in column A) are added up; the sum is always taken **one column at a time** (column 3 or column 4, never both); and when several cells hold the same value, a rule whose name says *Total* takes the lowest one (a total sits at the bottom of its column). If no column of the sheet is recognised as that currency, every column that is not another currency's is searched, reading the sheet itself if its cells were never extracted. On the off-balance by-currency sheet USD, EUR and GBP always get their own check, even when the sheet's header for them is not recognised. Such a rule is tagged **Found by value** and its note names the cell (or cells), the row and what the rule's own row held, so a coincidence is easy to spot. If the item rows add up to the pivot but the sheet's own total row holds another number, the rule **stays a variance** (the sheet does not add up) and the note says so. Amounts under 10,000 are never searched this way. Rules that already match are left alone. Switch it off with the checkbox on the Default Mapping page. The same idea is in Mapping Studio's **amount search**: *Look in "the column of the selected items' currency" / "every column" / one currency's column(s)*.
  - **Trial Balance and off-balance numbers are not mixed.** The off-balance checks use the Outstanding Report pivots only; the Trial Balance's `OB-` groups are not searched in the off-balance file by Depth Search and not compared with the off-balance sheets. Both are **options for when you are in doubt**: *Depth Search → "Also search the Trial Balance's OB- groups…"* and *Default Mapping → "Also compare the Trial Balance's OB- groups with the off-balance total"* (three rules on the main off-balance sheet's total row: IQD, foreign, total). `OB-` groups are shown in the group list as *Off-balance - checked from the Outstanding Report*, not as *NO RULE*.
- **Arabic submissions: translate or work in Arabic.** After you inspect the submission workbooks, any Arabic content (sheet names or cells) triggers a prompt before any sheet is shown: **English** — translate the files with a dictionary workbook you upload (Arabic in column A, English in column B, header in row 1), or **Arabic** — keep the files as they are; nothing proceeds until you press Proceed. Translation is the supplied translation script, unchanged in behaviour (spelling-variant-insensitive whole-cell and word-by-word replacement, sheet names translated and made unique, formulas' sheet references rewritten, translated cells left-aligned) but without its file pickers. Formulas become their saved results where Excel saved one; a formula Excel never calculated is kept as a formula. You get the translated workbook per file and a `Missing_Arabic_Words.xlsx` listing every Arabic term the dictionary lacked. `.xls` / `.xlsb` uploads are converted to `.xlsx` first. The Trial Balance and the Outstanding Report are not translated.
- **Depth Search works in either language.** It matches numbers, so Arabic files need no translation; column currency, totals, foreign-currency columns, stated scale ("بالآلاف", "المبالغ بآلاف الدنانير العراقية", "بالملايين") and Arabic-Indic digits (`١٢٣٬٤٥٦`) are all recognised, and file-type guessing understands Arabic names. Matching by *description* (auto-suggestions, saved mappings) needs both sides in the same language — translate the submissions if the TB is English.
- **Interface language: English / Arabic.** The switch at the bottom of the left rail (العربية | English) flips the whole interface — every page, table heading, notice and message — to Arabic with a right-to-left layout, and back; the choice is remembered in the browser. Data is never translated (account names, file and sheet names, amounts, category and bucket labels). Texts that come from the backend with embedded names (e.g. a specific warning) stay in English if no translation exists. The translations live in one dictionary at the end of `webapp.js`.
- Run the reconciliation, then review the full Reconciliation Map — every TB group and sub‑group with its approved submission evidence (file, sheet, cell, amount), plus a dedicated section for manual/imported matches that carry their own label — before exporting the audit workbook.

## Notes
- Files are stored only in a temporary backend session directory; no managed folder is used.
- When a default/imported mapping item resolves to a TB description, it now sums **every** TB line carrying that description (narrowed to the named account number when the mapping gives one) instead of only the first line, and never counts the same TB line twice across items.
- Downloads (the reconciliation workbook, the simplified submissions export, and the TB pivot) use `fetch()` → `blob()` → a programmatic `<a download>` click, not a direct `window.location` navigation — this matters because Dataiku embeds the WebApp in a sandboxed iframe, where a top-level navigation to a download URL can be silently blocked by the browser. A failed fetch now also surfaces the backend's JSON error as a toast instead of navigating the app away to raw JSON.
- The TB pivot and extracted-submissions previews shown in the UI are capped at 20,000 rows (raised from much lower internal caps that could silently make a large, fully-processed multi-file/multi-sheet upload look incomplete in the browser, even though the underlying session data, auto-matching and full workbook export were never actually truncated).
- `engine.py` and `backend.py` were audited for Python-version-sensitive syntax (`removeprefix`/`removesuffix`, dict-merge `|`, walrus `:=`, `match`/`case`) and contain none; both parse cleanly under `ast.parse()`. The full backend test suite has been run and passes against Python 3.10, 3.12 and 3.14 (with current `pandas`/`numpy`/`openpyxl`/`Flask` versions on 3.12). Python 3.9 and 3.11 specifically were not available to test directly in this environment — if deploying to one of those exact interpreters, re-run the test suite there once before going live.
- The generated TB Pivot is a normal Excel summary sheet, not an Excel PivotTable cache object. It contains the requested hierarchy, currency columns, and summed Adjusted Balance.
- The exported workbook adds an Auto Suggestions sheet and a Reconciliation Map sheet (flattened lineage) alongside the original summary/pivot/detail/submission/results sheets.
- A rule that resolves to zero components on both sides (e.g. an imported mapping match that couldn't be found in the new data at all) is reported as `UNRESOLVED`, never as a trivial 0‑vs‑0 match — always check for that status after importing a mapping.
- The webapp has no inline `on*` event handlers (CSP-safe) and every backend route always returns JSON, including on error — this matters if the WebApp is embedded behind a proxy that enforces a strict Content-Security-Policy.
- For multi-user production deployment, replace the in-memory `SESSIONS` dictionary with an approved shared session store and apply the organisation's retention and access controls.
